# DevFolio Framer 작업

루트 [AGENTS.md](../../../AGENTS.md)의 보안·변경 경계를 따른다. [콘텐츠](../../../docs/PORTFOLIO_CONTENT.md), [Works](../../../docs/PROJECTS.md), [디자인 기준](../../../docs/DESIGN_GUIDE.md), [실행 프롬프트](../../../prompts/START.md)를 작업 목적에 맞게 읽는다.

## 연결과 읽기 전용 조사

대상 ID는 a4DYM9E5gPhRx0PF4qQU다. 연결된 Framer 도구만 사용하며 @framer/agent CLI나 별도 framer/framer-code-components CLI 스킬로 우회하지 않는다.

1. 유효 세션을 재사용한다. 없을 때만 open_project를 호출한다. 프로젝트 ID·이름·활성 브랜치를 확인한다.
2. 반환된 README와 context.md를 먼저 읽는다. 작업에 해당하는 카탈로그 스킬과 API 문서를 적용하고 분할 문서는 순서대로 한 파트씩 읽는다.
3. api.tree 사용 전 tree API 문서, CMS 조사 전 CMS 스킬과 CMS 문서를 읽는다. 문서에 없는 API를 추측하지 않는다.
4. 필요한 페이지·브레이크포인트·템플릿·스타일·CMS 스키마/ID/바인딩을 읽기 전용으로 조사한다. 내용 전체를 덤프하지 말고 보안 범위에 맞는 요약만 가져온다.
5. 접근이 실패하거나 대상이 다르면 수정하지 않는다. 오류와 미검증 범위를 보고하고, Framer 연결 계정 및 대상 프로젝트 접근 권한을 확인하도록 안내한다. 권한 변경 후 같은 프로젝트를 다시 검증한다. 프로젝트 생성·remix·다른 도구로의 권한 우회를 하지 않는다.

현재 설정 요청에서는 Framer 읽기만 허용한다. 후속 편집 요청이 없는 상태에서 문서를 적용한다는 이유로 CMS나 화면을 변경하지 않는다.

## 콘텐츠와 CMS

기존 Works의 item ID와 slug는 PROJECTS.md의 대응표를 참고하되 라이브 상태를 다시 확인한다. 실제 6개 프로젝트를 기존 7개 항목에 덮어쓰기 위해 정렬 위치만으로 대응하지 않는다. 추가 항목은 보존한다.

프로젝트 문서는 CMS 필드별 초안이며 업로드 명령이 아니다. 후속 승인된 편집에서도 컬렉션·필드·slug·참조·Draft/Live 상태를 보존하고 CMS 바인딩 대상은 원본 항목을 수정한다. 표시 노드의 바인딩을 정적 텍스트로 바꾸지 않는다. richtext가 빈 문자열로 읽혀도 읽기 방식과 실제 하위 블록을 확인하기 전 비어 있다고 단정하지 않는다.

미확인 Career 날짜·공식 직함·기술 경험·정량 성과는 확정하지 않는다. 사내 사례는 일반화된 문구만 사용하고 사내 원본, 시스템 화면, 개인정보 및 인증 정보를 저장하거나 첨부하지 않는다.

## 디자인과 반응형

DevFolio의 기존 다크 테마·색상 토큰·컴포넌트·레이아웃·모션을 재사용한다. 한국어 문장과 영어 기술명을 사용한다. 한국어 폰트와 줄바꿈 보정은 디자인 가이드의 제안과 현재 적용 값을 구분한다.

후속 편집 전 현재 노드를 다시 읽는다. Layout Template이 소유하는 구조와 breakpoint 상속을 보존한다. 이미 정상인 구조를 선호 패턴으로 재구축하지 않는다. 템플릿 인물·추천사·가격·기술을 실제 이력으로 전환하지 않는다.

## 검증과 결과

GitHub는 별도 브랜치와 PR로 관리하고 main에 직접 쓰거나 병합하지 않는다. GitHub 브랜치와 Framer 브랜치는 별개다. Publish와 배포는 금지한다.

문서만 변경했다면 diff·README·링크·스킬 메타데이터·민감정보를 확인한다. 실제 UI 편집 시 1200/810/390px와 중간 폭·좁은 모바일에서 overflow, 메뉴, CTA, 카드, CMS 목록/상세와 키보드 사용을 검증한다. 부분 실패는 반영 상태를 먼저 확인한다. 기존 진단과 새 문제를 구분한다.

PR 링크, 실제 변경 범위, 수행한 검증, 접근 한계와 미확인 사항을 한국어로 보고한다. 읽기 확인을 편집·검증·게시 성공으로 표현하지 않는다.
