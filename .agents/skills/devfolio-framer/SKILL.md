# DevFolio Framer 작업

저장소 루트 AGENTS.md의 대상과 변경 경계를 따른다. 실제 화면과 CMS는 Framer가 기준이며, GitHub는 지침·초안·검증 기록을 관리한다.

## 연결과 현황

- 대상 프로젝트 ID는 `a4DYM9E5gPhRx0PF4qQU`이다. [연결 기록](../../../docs/framer-connection.md)은 과거 검증 근거이며 현재 접근 권한을 보장하지 않는다.
- 연결된 Framer 도구만 사용한다. `@framer/agent` CLI나 별도 framer/framer-code-components CLI 스킬로 우회하지 않는다.
- 유효 세션이 없을 때 open_project로 대상을 연다. 반환된 README, context.md를 순서대로 읽고, 카탈로그에 있는 관련 스킬과 API 문서를 작업 조건에 따라 읽는다. 문서의 분할 파트는 순서대로 하나씩 읽는다.
- 프로젝트 ID, 이름, 활성 브랜치를 확인한다. 다른 프로젝트이거나 접근할 수 없으면 쓰기를 멈추고 정확한 오류와 필요한 입력을 알린다. 세션 핸들은 실행 중에만 사용한다.
- 연결 확인 후 필요한 페이지, 브레이크포인트, 컴포넌트, 스타일과 CMS 연결을 읽기 전용으로 조사한다. `api.tree`를 쓰기 전 tree API 문서를 읽고, CMS 조사에는 프로젝트의 CMS 스킬과 문서를 먼저 읽는다. 지원하지 않는 API를 추측하지 않는다.

## 콘텐츠와 편집

현재 작업이 문서 설정 또는 조사라면 Framer는 읽기 전용으로 유지한다. 실제 편집 요청이 들어오면 요청 범위와 현황을 비교해 필요한 변경을 준비하고 적용한다. 정보가 부족한 부분은 초안에서 '미확인'으로 표시하고 공개될 화면에 허위 내용을 넣지 않는다.

기존 DevFolio의 레이아웃, 반응형 구조, 컴포넌트와 스타일을 우선 재사용한다. 구조 변경 전 CMS 컬렉션·필드·항목 ID와 바인딩을 확인한다. 기존 CMS는 삭제하거나 초기화하지 않는다. 파괴적 변경이 필요한 제안은 실행하지 않고 대안과 영향만 설명한다.

GitHub 작업은 main 이외의 작업 브랜치에서 수행한다. GitHub 브랜치를 만들었다는 이유로 Framer 변경이 격리됐다고 판단하지 않는다. Framer의 활성 브랜치와 변경 대상을 확인한 뒤 사용자 요청 범위에서만 수정한다. Publish와 배포는 수행하지 않는다.

## 검증과 인계

- 쓰기 직전 실제 노드를 다시 읽고 수동 편집을 보존한다.
- 변경한 화면은 가능한 미리보기/스크린샷과 진단으로 확인한다. 데스크톱·태블릿·모바일의 텍스트 넘침, 메뉴/링크, 이미지와 CMS 목록·상세 연결을 변경 영향에 맞게 검증한다. 확인하지 못한 항목은 명시한다.
- 부분 실패 후에는 반영된 상태와 진단을 먼저 읽고 실패한 부분만 수정한다.
- 저장소 변경은 diff와 README 보존 여부를 확인한다. 결과 보고에 GitHub 브랜치/커밋 링크와 실제 Framer 변경 범위, 검증 결과, 필요한 사용자 자료를 남긴다. 읽기 전용 작업에서 편집 완료나 게시 완료를 주장하지 않는다.
