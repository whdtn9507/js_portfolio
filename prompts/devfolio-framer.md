# DevFolio 실행 프롬프트

아래 요청문을 이 저장소의 작업 브랜치에서 사용한다. 첫 실행은 현황 조사와 작업안 작성이며, Framer 화면 편집은 후속 요청으로 지정한다.

---

GitHub `whdtn9507/js_portfolio`를 한종수의 Framer DevFolio 포트폴리오 작업 공간으로 사용해줘.

1. 루트 AGENTS.md와 .agents/skills/devfolio-framer/SKILL.md, docs/framer-connection.md를 읽어줘. 기존 README.md를 보존하고 GitHub main은 직접 수정하지 마. 현재 브랜치를 확인하고, main이면 `work/devfolio-framer-setup` 또는 별도의 새 작업 브랜치에서 진행해줘.
2. Framer 프로젝트 https://framer.com/projects/a4DYM9E5gPhRx0PF4qQU 에 연결 가능한지 재검증해줘. 유효 세션을 재사용하거나 프로젝트를 열고, 반환된 README와 context.md부터 필요한 문서를 읽어줘. 프로젝트 이름과 활성 브랜치를 확인해줘. 접근 실패 시 대체 프로젝트 생성 없이 오류와 필요한 조치만 알려줘.
3. 첫 실행에서는 Framer를 읽기 전용으로 조사해줘. 필요한 문서/스킬을 적용한 뒤 페이지, 반응형 구조, 주요 섹션, 컴포넌트/스타일, CMS 컬렉션과 연결 구조를 확인하고 수정 후보를 정리해줘. 템플릿 예시와 한종수의 확인된 정보를 구분해줘.
4. 기존 CMS를 삭제·초기화하지 말고 Publish·배포도 하지 마. GitHub 브랜치가 Framer 편집을 격리한다고 가정하지 마. 이번 프롬프트만으로 Framer 화면이나 데이터를 수정하지 마.
5. 실제 이력과 프로젝트 자료에서 부족한 입력을 정리하고, 기존 디자인을 살린 콘텐츠/화면 변경안을 작업 브랜치의 `docs/devfolio-work-plan.md`에 작성해줘. 추측한 경력·성과·연락처를 실제 정보로 쓰지 마.
6. 연결 결과, 조사 범위와 미검증 항목, 생성한 문서 링크, 다음 편집에 필요한 입력을 한국어로 보고해줘.

이후 사용자가 구체적인 편집을 요청하면 그 범위 안에서 작업을 이어가되 README 보존, CMS 삭제 금지, GitHub main 직접 수정 금지, Publish 금지를 유지해줘.
