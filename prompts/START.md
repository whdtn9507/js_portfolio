# DevFolio 실행·검증 프롬프트

이 문서를 작업 요청과 함께 사용한다. 목표는 한종수의 Software Builder / Software Engineer / UI Publisher 포트폴리오다. 기본 실행은 읽기 전용 분석과 문서 작업이며, 화면·CMS 수정은 구체적인 후속 요청이 있을 때만 수행한다.

## 실행 요청

GitHub 저장소 whdtn9507/js_portfolio와 Framer 프로젝트 https://framer.com/projects/a4DYM9E5gPhRx0PF4qQU 를 대상으로 작업해줘.

1. AGENTS.md와 .agents/skills/devfolio-framer/SKILL.md를 읽고, docs/PORTFOLIO_CONTENT.md, docs/PROJECTS.md, docs/DESIGN_GUIDE.md를 확인해줘.
2. 저장소 상태와 최신 main·작업 브랜치·기존 PR을 읽기 전용으로 확인해줘. 기존 README는 그대로 유지하고 별도 브랜치에서 진행해줘. main에 직접 commit/push하거나 PR을 병합하지 마.
3. Framer의 유효 세션을 재사용하거나 프로젝트를 열고 README → context.md → 관련 스킬·API 문서를 읽어줘. 실제 프로젝트와 활성 브랜치를 확인해줘. 연결 실패 시 수정 없이 오류, 미검증 범위와 연결 복구 방법을 보고해줘. 프로젝트 생성·remix로 대체하지 마.
4. 페이지, breakpoint, Layout Template, 스타일, CMS 스키마·item ID·slug·바인딩·상태를 필요한 범위에서 읽기 전용으로 분석해줘. 전체 사내 자료를 덤프하지 마.
5. 현재 구조, 변경할 파일/화면, 근거와 미확인 사항, 생성 계획을 먼저 보고한 후 요청 범위에서 작업해줘. 문서만 요청했으면 Framer는 계속 읽기 전용으로 유지해줘.
6. 목표 포지셔닝을 유지하되 공식 직함과 혼동하지 말아줘. 한글 본문과 영어 기술명을 쓰고, 기존 DevFolio 디자인과 다크 테마를 유지해줘.
7. 실제 6개 Works는 기존 ID·slug와 대응시켜줘. 기존 7번째 항목을 지우거나 6개 요구를 맞추기 위해 CMS를 초기화하지 마. 기존 데이터·참조·바인딩·Draft/Live 상태도 보존해줘.
8. 미확인 경력·기술 숙련도·기여율·성과를 만들지 마. 샌드박스 재직기간과 일부 기술의 개인 사용 범위는 확정하지 말아줘. 템플릿 추천사·가격·인물을 실제 정보로 쓰지 마.
9. 사내 계약서·인감·서명·계약번호·운영 로그·사내 시스템 화면·개인정보·비밀 값을 파일, 이미지, PR에 저장하지 마. 사내 사례는 일반화된 설명만 쓰고, 도식이 필요하면 가상 데이터를 사용해줘.
10. Publish·배포·도메인 변경은 하지 마. GitHub 브랜치가 Framer 편집을 격리한다고 가정하지 마.

## 검증 요청

변경 범위에 맞는 검증을 수행하고 실제 결과만 보고해줘.

- diff에서 요청 파일, README 불변, 기존 보조 문서 보존, 민감정보·임시 파일 미포함 확인
- Markdown 상대 링크, 프로젝트 6개 ID/slug 대응, 스킬 frontmatter 및 미완성 scaffold 확인
- 가능하면 skill-creator의 quick_validate.py 실행. 환경이나 의존성이 없으면 실패 원인과 대체 검사를 분리해 보고
- 사실·미확인 항목 구분, 목표 직무와 공식 직함 구분, 프로젝트 결과와 성능 지표 구분 확인
- 문서 작업이라면 Framer changedNodeCount 0과 작업 전후 페이지/CMS 수 확인. 실제 UI 기능 테스트를 통과했다고 주장하지 않음
- 후속 UI 편집이 있다면 디자인 가이드의 폭별 가독성·overflow·메뉴·CTA·CMS 목록/상세·키보드 사용을 검증. 제출/메시지 발송 같은 외부 동작은 실행하지 않음
- 접근하지 못한 항목, 미검증 폭/페이지/기능, 남은 사용자 확인을 명시

문서 변경을 작업 브랜치에 커밋하고 PR로 제출해줘. PR에는 문제와 결과, Framer 변경 여부, 검증 결과와 한계를 적고 최종 답변에 PR 링크를 남겨줘. 기존 PR과 변경이 겹치면 관계를 설명하되 임의로 닫거나 병합하지 마.

## 접근 실패 시 안내

Framer 연결 계정이 대상 프로젝트에 접근 가능한지 확인하고, 같은 계정에서 프로젝트 링크를 열 수 있도록 공유/권한을 확인하도록 안내해줘. 필요한 경우 Framer 연결을 재인증한 뒤 동일 프로젝트 ID로 읽기 검증을 다시 수행해줘. 공개 preview 접근만으로 편집 권한이 있다고 판단하지 마.

GitHub 403은 저장소 선택과 설치 앱의 권한을 구분해 보고해줘. 이미 허용된 작업을 반복 승인 요청으로 대체하지 말고 가능한 문서·검토 작업을 완료해줘. 실제 권한 제한을 다른 자격 증명으로 우회하지 마.
